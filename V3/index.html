P-01 / 2026

AgentForge - Multi-Tenant AI Coding Agent

Python · FastAPI · Next.js · PostgreSQL · Redis · Docker
Flagship build

An autonomous agent that analyses any GitHub repository, plans a change, edits code through a tool-use loop, runs the project's own test command and opens a pull request. The interesting design decision is that it stops before touching GitHub: when tests pass the task halts at ready for review, and a human approves the plan, the diffs and the test output before anything is published - human-in-the-loop by architecture, not by policy.

Reliability for long-running LLM jobs is the hard part. Redis leases prevent duplicate execution, a heartbeat reaper detects crashed workers, and progress streams live over Server-Sent Events. Every provider call is recorded with tokens, cost and latency, so a Usage dashboard shows exactly what each run spent. All AI access sits behind one provider interface - Anthropic and Gemini implemented, others registered - so switching model or provider is an environment variable, never a code change.

Repository intelligence detects languages, frameworks, entry points, API routes and SQL schemas, then produces a 0–100 health score with deterministic sub-scores and grounded improvement suggestions - every suggestion must cite real files, and anything undeterminable is reported as such rather than guessed. Safety is enforced, not assumed: secrets and credential files are never read, tokens are injected via git headers and scrubbed from all logs, archive extraction is zip-slip guarded, and the one destructive database command requires typing a confirmation phrase.

P-07 / 2024

SnapBin - Civic Waste Reporting, Ireland-first

Kotlin · Java · Android · Firebase · Google Vision API · AWS EC2 / S3 · REST · MVC
Final Year Project

My BSc Computer Science final year project, and Ireland's first civic waste-reporting Android app. Illegal dumping is reported through council phone lines and web forms that ask people to describe a location in words - so reports arrive vague, unverifiable and slow to triage. SnapBin replaces that with a single action: point the camera at the problem and submit.

A photo is classified on submission through the Google Vision API to identify the waste type and reject non-waste images before they ever reach a council queue, while GPS coordinates and a timestamp are attached automatically - every report arrives geolocated, categorised and time-stamped instead of hand-described. Duplicate submissions at the same location are clustered rather than filed twice, so a single fly-tipping site doesn't generate fifty separate tickets.

The Android client was built in Kotlin and Java on an interface-driven MVC architecture, with Firebase handling authentication and real-time status sync so a citizen can watch their report move from submitted to acknowledged to resolved. Media and report data are served by a REST backend on AWS EC2 and S3, structured so image storage scales independently of the reporting API. The result was adoption up 50% in three months, and a working argument that civic reporting fails on friction, not on public willingness.

P-08 / 2023

Taskit - Jobs Without the Language Barrier

Mobile · Multilingual UX · Localisation-first architecture · Built in Oulu, Finland
Finland-first

Finland's first multilingual local job-finder built specifically for people who don't speak Finnish. I designed it while living the problem as an Erasmus student in Oulu: the work exists - cleaning, warehouse, kitchen, delivery, seasonal shifts - but the listings, the application forms and the employer messages are all in Finnish, so the barrier isn't skill or availability, it's language.

Taskit treats language as infrastructure rather than a settings toggle. Listings are stored language-agnostically and rendered per user, so a Finnish employer posts once in Finnish and an applicant reads it in their own language without either side changing how they work. Roles are filtered by the Finnish level a job actually requires - a warehouse shift needing none shouldn't be buried under office roles needing fluency - and listings carry location, pay and shift structure up front, since those are the fields that decide whether a job is even viable for someone without a car or a residence permit history.

The build taught me that localisation is an architectural decision made on day one, not a translation pass bolted on at the end - which is why the RAG system in my thesis serves four languages from a single grounded knowledge base, and why this site speaks seven.
